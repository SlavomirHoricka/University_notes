# Course records, freshness, and handoff

> Historical v2 protocol. The current ownership contract is in 03_Agents/LEARNING_ARCHITECTURE.md and the plan, teach, and recall skills. Do not use this document to give the tutor plan or source-manifest write access.

Version 2, 2026-10-03. These are pragmatic record-keeping rules, not a validated psychometric model. Use three Markdown files in the selected course's mirrored `03_Agents` directory; no database, copied course assets, or scheduler is needed. Initialize and maintain them automatically during requested teaching; the learner does not fill out these schemas.

## One place for each kind of information

| File | Canonical responsibility |
|---|---|
| `learning_plan.md` | Identity, scope, objective definitions and criterion versions, justified prerequisites, sequence, coverage, evidence-backed objective status, plan version and changes. |
| `learning_log.md` | One compact `Current state` section for where to resume and which objectives remain time-deferred; append-only chronological events for session plans, actual attempts, exposures, corrections and scheduler proposals. |
| `source_manifest.md` | Watch scope, exact paths/hashes, immutable dated source snapshots, semantic baselines, source-to-objective mapping and changes. |

Never duplicate current position in the plan or rewrite historical attempts when refreshing the summary. The plan's objective status is a derived index citing event IDs; events remain the evidence. If index and events disagree, reconcile from committed evidence and append the correction. Source snapshots and objective revisions are versioned so older event references remain interpretable.

## IDs, time, and values

- `course_id`: exact `<year>/<semester>/<course>` path; store course code separately, `null` if absent. Stable objective IDs such as `O001` are unique within that course and never recycled; fully qualify cross-course references.
- `plan_version`: `P001`, increment for changed objective definitions, criteria, dependencies, or sequence/scope. `source_version`: `V001`, increment for any manifest change. A timestamp-only metadata refresh may keep the version if hashes, paths and scope are unchanged. Routine evidence-index updates do not change the curriculum version; use `record_revision` for each file write.
- `session_id`: UTC start timestamp plus short collision-resistant suffix, e.g. `S-<UTC timestamp>-<suffix>`. `event_id` and `attempt_id` are unique within the course; an attempt can have several events. Preserve IDs on retries to avoid duplicate append.
- All actual timestamps: ISO 8601 with offset, plus `timezone: Europe/Prague`. Determine the offset for the event's actual date, respecting summer/winter time. UTC IDs do not replace the local timestamp. Date-only scheduling uses `YYYY-MM-DD` and the zone. Obtain actual time from the environment, not from a guessed session length.
- `null` means unknown/not measured; `[]` means known empty. Use `not_applicable` only where no value applies. An observed blank answer is different from no received response. Do not convert file modification times into study times or old notes into dated assessments.

## Objectives and evidence states

An objective states an observable action, content, conditions, and criteria. Record knowledge type and Bloom process as descriptors, not numeric levels. Each objective needs source locations (page/heading), a concise source-grounded content/assumption digest, prerequisite IDs with rationale, accepted response components, critical errors, and planned immediate/delayed/transfer assessment forms as applicable. A plan can be provisional and partial; unsourced syllabus completeness stays unknown.

| Field | Allowed states and meaning |
|---|---|
| `learning_status` | `unassessed`: no interpretable performance evidence; `practicing`: learning begun or evidence partial/assisted; `independent`: distinct independent checks met the explicitly recorded `evidence_criterion_version`. It licenses current advancement only when that evidence applies to the current criterion and the gate is clear. |
| `retention_status` | `untested`: no independent acquisition evidence yet; `pending`: independent evidence exists but the intended delayed check remains; `observed`: dated delayed retrieval met its criterion for that interval; `gap`: delayed performance failed or was partial. |
| `reassessment_gate` | `clear`, `required`, `deferred`, or `blocked_source`; give reason, affected objective/criterion versions and evidence references. `clear` is a workflow condition, not proof of knowledge. |

These fields are orthogonal: an objective may be `independent / pending / clear`. A source correction can make it `independent / observed / required`: keep `evidence_criterion_version` pointing to the old criterion so the historical result cannot be mistaken for current validation. After new evidence, update the index for the current criterion. A delayed failure normally makes current learning status `practicing` and retention `gap`; preserve the earlier independent result in history. For an untested changed objective use `unassessed`, not “forgotten.” Retire removed objectives with a reason; never delete their evidence or silently reuse IDs for a different meaning.

## Attempt and event contract

Each event has `event_id`, `recorded_at`, `occurred_at` (or `null`), timezone, writer/role, event type, session ID if applicable, and plan/source versions. Useful types: `session_started`, `session_plan`, `session_plan_update`, `attempt_started`, `attempt_result`, `instruction_or_feedback`, `source_reconciled`, `checkpoint`, `session_paused`, `session_closed`, `correction`, `schedule_proposal`, `schedule_update`, `commit`. Session state is `not_started`, `active`, `paused`, `closed`, or `interrupted`; closing a session does not mean completing its objectives. One compact event can contain both a result and its subsequent feedback with explicit order/times; do not imply the feedback preceded the scored response.

A `session_plan` records `time_budget_minutes` as learner-reported or `null` if unknown, the requested scope, candidate objective IDs (including relevant prior time deferrals), ordered selected IDs, and IDs newly deferred **because of time**. Give a short priority reason for each selected or time-deferred objective: due review, blocking dependency, importance in the course notes, learner-stated assessment goal/deadline, observed weakness, earlier time deferral, or fit with remaining time. If the route changes, append `session_plan_update` with the changed selection and reason; do not rewrite the earlier plan. At pause or closure, reconcile selected objectives against actual events. Carry forward previously deferred IDs that remain unstudied, plus new time deferrals, into `Current state`; a new request on another topic does not silently erase them. Remove an ID when it is studied or the learner explicitly drops it from the intended scope, and record why. Time deferral is a session-planning fact, separate from `reassessment_gate: deferred`, and never proves an objective was studied. When the learner gives no duration, keep `time_budget_minutes: null`; do not substitute elapsed wall time.

An assessed attempt additionally records:

| Field | Required meaning |
|---|---|
| `attempt_id`, `objective_ids`, `criterion_versions` | The specific objective and rubric being assessed. |
| `phase` | `diagnostic`, `initial_learning`, `immediate_practice`, `delayed_retrieval`, or `reassessment`; record purpose separately when both reassessment and delayed retrieval apply. |
| `task_ref`, `task_text_or_digest`, `item_version` | Stable source page/question or enough exact task content to distinguish variants. Store generated short items in the event, including numbers and conditions needed to interpret the response. |
| `task_relation` | `same_item`, `parallel_variant`, `near_transfer`, `far_transfer`, or `unknown`; explain what changed. A change of numbers alone is not evidence of broad transfer. |
| `criteria`, `response_evidence`, `outcome` | Essential rubric components; concise observed reasoning/answer; `met`, `partial`, `not_met`, `incomplete`, or `unscorable`. Numeric score optional with explicit denominator and rubric; never invented. |
| `assistance` | `none`, `cue`, `strategy_hint`, `partial_worked`, `full_solution`, or `unknown`, plus actual hint content/count. Preserve the pre-hint attempt outcome separately. |
| `note_access`, `solution_exposure` | `closed`, `open`, or `unknown` for notes; `none`, `prior_same_session`, `during_attempt`, or `unknown` for solution exposure. Record tools/calculator access where relevant. Independent evidence requires known unaided conditions appropriate to the criterion; closed-note status is learner-reported, not proctored. |
| `confidence_before_feedback` | Optional 0–100 or `null`, with the question asked; not inferred from writing style and never substituted for correctness. |
| `errors_or_misconceptions`, `feedback`, `next_need` | Observed error versus tentative interpretation; correction supplied; what remains to do. Use `[]`/`null` honestly. |
| `previous_attempt_id`, `last_relevant_exposure_at`, `intervening_exposure` | Links and timestamps sufficient to compute real elapsed time; known restudy, tutoring, feedback or reported independent study counts as exposure. Unknown exposure makes the retention interpretation qualified. |

Record instruction and significant restudy even without a quiz, so a scheduler does not mistake time since last test for time since last exposure. An attempt without a response is `incomplete`, never wrong. Feedback is an intervention, not a learner accomplishment. Corrections to scores append a new event with `supersedes_event_id`, reason and corrected interpretation; preserve the original.

## Freshness: inspect changes before updating the baseline

1. **Define a bounded watch scope.** Enumerate the selected course note and materials directories, the hub, relevant shared/cross-course files and source-linked attachments. Directory enumeration detects new unlinked lectures. For a narrow lesson, list all course file paths but inspect only relevant contents; classify other entries `candidate_uninspected` or `out_of_scope` with reasons. Hash entries in the recorded watch scope, including uninspected candidates, so old/new comparisons are real. Do not include `03_Agents`, backups, app configuration, or generated state. The watch scope and deferred coverage are explicit; it is not a whole-vault guarantee.
2. **Fingerprint actual bytes.** Store exact vault-relative path, SHA-256 of complete raw contents (including binaries), byte size, modification time with offset, kind, inspection coverage, and objective associations. Use file tools/standard hash utilities. Rehash watched files on resumption; timestamps and size are supporting metadata only. For a large course, stream hashes without reading content into context. If a file changes while hashing/reading, retry until stable or mark it unstable and block affected claims. A read error is `hash: null` with a reason, not a deletion.
3. **Compare against the last committed snapshot.** Detect additions, changed hashes, disappeared paths, and directory access failures. Identical hashes at an old/new path suggest a rename; duplicate identical files make this ambiguous, so inspect links/metadata. Rename plus edit requires identity evidence; otherwise retain add/delete with uncertain correspondence. Preserve aliases and anchors when updating agent references. Do not rename source files.
4. **Check link changes and relevance.** Reinspect links in changed notes and the hub, re-resolve known missing/ambiguous targets, and add newly relevant sources/attachments to scope. A new external link is a coverage candidate; record retrieval time and a content digest/hash if inspected, or `uninspected_external` otherwise. A URL alone is not a stable content baseline. No login or submission is authorized by a source link.
5. **Determine meaning, not just byte difference.** Every inspected source row has a compact semantic baseline keyed to its hash: relevant claims, assumptions, formulas, syllabus expectations, locators, and mapped objective IDs. Retain these digests in prior snapshot blocks; retain old objective/criterion definitions in plan revision notes. Compare current content against those baselines. Use a prior file revision if already available, but do not require Git or copy all notes/assets into agent memory. A digest may omit a detail: say `semantic_change_uncertain` when it cannot establish what changed. Never call an unexplained hash change formatting-only. Inspect mathematical signs, conditions, figure changes, and anchor movements, not just prose.
6. **Reconcile only the affected scope.** Classify `unchanged`, `formatting_only`, `path_only`, `new_content`, `substantive_correction`, `deleted`, or `uncertain`. Append a dated source-change event with old/new versions, mapping, reason and affected prerequisites/downstream objectives. Update criteria/sequence if needed, retaining prior versions. New objectives start unassessed; previously demonstrated affected claims receive a required gate. Deletion does not erase learning: determine whether scope changed or a necessary source is now missing.
7. **Commit, then target the retest.** Save the reconciled plan and new source snapshot using the transaction procedure below. Acknowledge a correction to previously taught content explicitly. Target the changed claims and justified dependencies, not a full-course exam. Diagnose newly added content as new. If the learner declines, record `deferred` with the reason if given; postpone dependent new learning/assessment credit and offer unaffected work. Missing authoritative content produces `blocked_source`, not a guessed answer. Clear a gate only with cited adequate new evidence or a documented finding that no learning claim was affected.

No manifest: establish a baseline now and label historical changes unknown. No log/evidence: preserve the existing plan but mark unsupported status claims unverified; do a bounded diagnostic before relying on them. Source and history gaps are different from demonstrated errors.

## Checkpoints and safe writes

Use the log as a journal. Before an assessment, append its start with the task and intended criterion; after a response, append the result and feedback. Save at meaningful milestones, not only on goodbye. Keep the current state compact: session start, reported time budget, objective/step begun, last committed event, last completed step, stopping point, pending attempt, next intended step, plan position, time-deferred objective IDs, blocking misconceptions and reassessments. Detailed priority reasons and errors remain in linked events. At the next session, reread those reasons and reconsider each time-deferred objective alongside due reviews, prerequisites, new requests, and deadlines; do not silently drop it or automatically rank it first.

**Cooperating writers:** before any update, acquire an exclusive course lock using atomic directory creation of `.learning-write.lock` in that agent-course directory. Store owner/session and creation time inside. All tutor and scheduler writers must use it. If held, do not overwrite, steal it based only on age, or wait indefinitely: retain the pending event and retry later. A stale lock requires checking that its owner is inactive; if that cannot be established, report the conflict. The lock is operational metadata, not learner evidence.

While holding the lock, reread all files to be changed and compare revisions/hashes with those read earlier. Merge fresh append-only events by ID, preserve other writers' fields and scheduler entries, and recompute only the tutor-owned current state from committed events. Check the hashes again immediately before replacement. Unexpected external edits mean stop and reconcile; the cooperative lock cannot guarantee safety against an editor that ignores it.

For a checkpoint spanning files, assign `transaction_id`: (a) atomically append journal events with this ID, initially uncommitted; (b) write plan/manifest and a proposed state tagged with the same ID through temporary sibling files and atomic replacements; (c) append a `commit` event once all replacements succeed. Preserve original files until replacements are ready. Each write advances `record_revision`. Release only your own lock in cleanup. Atomic replacement protects a single file, not the entire transaction.

On recovery, read events after `current_state.last_committed_event_id`. An uncommitted transaction is not finished progress: reconcile its staged file versions and journal before completing it or append an abort/correction. Rebuild state from committed observations only. A persisted response can be recovered; an unsaved response cannot be inferred. If only `attempt_started` exists, resume the unanswered item or explicitly abandon it and use a fresh variant if exposed. Record recovery time separately from unknown interruption time. Do not assign a fictional end time or duration.

## Scheduler handoff: a contract, not an active scheduler

Tutor owns objective/rubric definitions, status index, attempts, feedback, exposures, actual session events, source reconciliation, reassessment gates, and current-state summary. Scheduler reads these, computes intervals from actual times (prefer last relevant exposure as well as last independent success), and may append only `schedule_proposal`/`schedule_update` events. It never edits learner outcomes or marks a session completed.

Scheduler fields: `proposal_id`, `recorded_at`, `writer`, qualified objective IDs, plan/source/criterion versions, supporting event IDs, proposed local date/time or review window, timezone, rationale, priority, planned task type, and proposal state (`proposed`, `accepted`, `superseded`, `cancelled`). Reference an earlier proposal to update it; do not rewrite history. Tutor completion can reference `proposal_id`; a missed date has no assessment outcome. Scheduler proposals never occupy the canonical current-state section.

Research supports spaced retrieval and relearning but does not establish one optimum schedule for this learner. Consider target retention horizon/deadline, actual elapsed intervals, successful independent retrieval, failed/assisted retrieval, intervening exposure, and unresolved source gates. Start with manageable delayed checks, extend intervals after successful retrieval, and shorten/reteach after difficulty as adjustable planning heuristics. Never apply a universal forgetting curve, convert confidence into mastery, or create a completed event from a recommendation. Scheduling or notification requires a separate user request.
