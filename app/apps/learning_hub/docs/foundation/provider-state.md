# H01 private durable provider seam

Root serialized this foundation-owned extension while H03 waits. Input H02 accepted integration
`cc2972e839d9b03fa9ce5ffbe9375c03c4b3882b`; dependency commit
`588d8201af4677522b307e117168bf90175443f6`. Requested/configured native foundation role is
`gpt-6.1-sol` / `high`; independent runtime telemetry is unavailable.

The public API adds only root-approved provider lifecycle error codes to `ProblemV1`; its generated
OpenAPI/TypeScript artifacts are regenerated by the owning export script. `domain/models/provider_state.py` and
`domain/ports/provider.py::ProviderStateRepository` are private operational DTOs and ports.
`adapters/storage/provider.py::SQLiteProviderState` owns short transactions on an explicitly
provided, migrated SQLite connection. Open one connection per caller; do not retain transactions
across external IO. This implementation makes no auth, model, inference, or credential-store calls.

Migration `0006_provider_state.sql` adds versioned registrations, an active singleton pointer, and
run metadata; it extends existing auth flows with revision/error and strict transitions. Accepted
0001–0005 files remain byte-identical. Upgrading an existing DB requires a fresh backup, quiescence,
checksum validation and integrity checks through the existing migration runner. No production DB
was created or upgraded by this task.

Account state starts at revision 1 with no registration. `activate` requires an active account at
exactly expected revision + 1; `revoke` also increments the singleton. Previous registration rows
are retained. `mark_verified(settings, expected_revision, run_id)` requires the exact persisted,
completed, bound run for the active account and matching observed/requested settings; it creates a
new immutable registration revision. Identity/auth proof does not create inference proof.

`create_flow(action, flow)` atomically persists the human command, common `provider_action` receipt,
and pending flow. `revoke_action(action)` atomically revokes and persists the sign-out receipt.
Replay lookup precedes account revision checks and reuses the original receipt; changed request
hashes conflict. Flow registration retains client, redirect URI, original expected account revision
and expected returning subject; host metadata records only local instance and callback origin.
`complete_flow` atomically checks the original account CAS and returning subject/client, activates
an unverified registration, and transitions validating → completed. Expired flows cannot activate.
The root-approved initial supported SIWC registration is the single exception to client equality:
requested action `sign_in`, initial `dynamic_agent_client`, and no expected returning subject permit
the validated callback's nonempty issued client ID, which cannot retain the sentinel. No undocumented
issued-client prefix is assumed. Returning/grant flows retain exact expected client and subject.
H01 must verify token signature, issuer, issued audience, nonce and callback client before invoking
this trusted completion port. This exception does not relax grant or inference gates.
Other flow transitions use an exact flow revision. Terminal flows are immutable.

`prepare_run` binds a logical task hash to account revision, required grant scopes and requested
settings. Retries return the same run; different request/account/settings conflict.
`claim_run` verifies the still-active registration and grants and durably moves prepared → submitted
before RPC dispatch. Only a single caller can claim. Actual thread/turn IDs and observed settings
are retained once known. Terminal output is bounded to 200,000 characters and allowed only for
confirmed terminal states. No prompt, token, PKCE secret, private reasoning, or transcript log is
stored here. The provider owner supplies the protected flow blob keyed by flow ID.

An interrupted process must inspect this state. A submitted run without a bound turn becomes
`unknown`; it cannot be redispatched or resolved by inventing new IDs. An uncertain bound run can
only resolve to a confirmed terminal state with its original thread/turn identity. Replacing a run
or account cannot silently reuse the logical task. Provider recovery verifies actual app-server
turn history before calling a terminal transition.

This seam is not acceptance of real provider authorization or inference. H01 owns supported OAuth,
secret storage, RPC dispatch, actual settings validation and external proof. H03 and H09 evidence
writers remain disabled for production pending their separate gates.

Validation includes focused additive upgrade/backup/history, CAS, atomic replay/rollback, returning
subject and expiry, missing grants, pre-dispatch durability, unknown-run recovery, identity/settings
immutability, exact terminal inference verification, and public schema exclusion. H02 migration
regressions explicitly retain target 5, rather than changing the meaning of their acceptance cases.

The shared local authorization port adds `LocalAuthorizationError` with exactly four typed local
codes and constant redacted messages. `LOCAL_SESSION_COOKIE_NAME = "hub_session"` is the root-approved
shared default. H01 maps those codes to `ProblemV1`; H03 supplies actual cookie/Origin/CSRF checks.
This patch supplies only the exception/constant seam, never a permissive auth implementation.
